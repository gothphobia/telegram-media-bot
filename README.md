# Telegram Media Bot

Telegram-бот на Python: отправьте ссылку на **YouTube, YouTube Shorts или TikTok**, нажмите **MP4** или **MP3**, получите файл в чат.

- MP4: выбирается лучшее доступное видео и лучшее аудио, включая высокие разрешения, если источник их отдаёт. FFmpeg объединяет потоки и меняет контейнер без перекодирования. Если редкий исходный кодек нельзя поместить в MP4, бот вернёт ошибку. Файл отправляется документом, чтобы Telegram не пересжимал видео.
- MP3: извлечение аудио и кодирование с высоким качеством VBR (`-q:a 0`). Преобразование в MP3 не улучшает качество исходного звука.
- Собственные водяные знаки бот не добавляет. TikTok через yt-dlp часто отдаёт исходный поток без логотипа, но это зависит от конкретного видео и доступных потоков. Уже встроенные в изображение логотипы и надписи бот не удаляет.
- Отдельные видео, включая короткие ссылки TikTok. Плейлисты и активные трансляции не поддерживаются.
- Ограничения размера, времени и одновременных загрузок; автоматическая очистка файлов после отправки или ошибки.

## Быстрый запуск на macOS

Нужны Python 3.11+, FFmpeg и Deno (или Node.js 22+). Если Homebrew уже установлен:

```bash
brew install python ffmpeg deno
cd /Users/gothphobia/Documents/Codex/telegram-media-bot
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
cp .env.example .env
```

1. Откройте [@BotFather](https://t.me/BotFather), отправьте `/newbot`, задайте имя и username.
2. Вставьте полученный токен в `BOT_TOKEN` в файле `.env`. Не публикуйте токен.
3. Запустите:

```bash
python bot.py
```

Откройте своего бота в Telegram → `/start` → ссылка → выбор MP4 / MP3. Компьютер должен оставаться включённым, а процесс бота — работать. Вебхук и публичный адрес не нужны: используется long polling. На Linux зависимости FFmpeg устанавливаются через пакетный менеджер, Python-зависимости — теми же командами.

Для личного доступа отправьте боту `/id`, затем укажите свой числовой ID в `ALLOWED_USER_IDS` и перезапустите процесс. Несколько ID разделяются запятыми. Пустое значение разрешает пользоваться ботом всем.

## Запуск через Docker

Docker включает Python, FFmpeg, Deno и зависимости. Создайте `.env` из `.env.example` и заполните токен, затем:

```bash
docker compose up -d --build
docker compose logs -f
```

Остановить: `docker compose down`. Можно развернуть на постоянно работающем сервере. Не запускайте одновременно два экземпляра long polling с одним токеном.

## Большие видео и качество

Обычный [Telegram Bot API](https://core.telegram.org/bots/api#sending-files) принимает загрузки до **50 МБ**; по умолчанию задан запас — **49 МБ**. Бот сообщает о превышении лимита и не снижает разрешение автоматически. Поэтому длинное YouTube-видео в высоком качестве обычно не поместится.

Для отправки больших исходных MP4 нужен собственный [Telegram Bot API server](https://github.com/tdlib/telegram-bot-api), допускающий загрузки до **2000 МБ**:

1. Разверните официальный сервер по его README с собственными `api_id` и `api_hash`, полученными на [my.telegram.org](https://my.telegram.org). Потребуется параметр `--local`. Сервер Bot API и этот бот — отдельные процессы; в Dockerfile проекта включён только бот.
2. При переходе с облачного API остановите бота и один раз вызовите метод `logOut` у старого облачного API. Можно выполнить локально, не вставляя токен в командную историю:

```bash
source .venv/bin/activate
python -c 'import urllib.request; from config import Config; c=Config.load(); print(urllib.request.urlopen("https://api.telegram.org/bot"+c.token+"/logOut").read().decode())'
```

3. Укажите в `.env` адрес доступного серверу бота Bot API и лимит:

```dotenv
TELEGRAM_API_BASE=http://127.0.0.1:8081
MAX_UPLOAD_MB=1990
DOWNLOAD_TIMEOUT=1800
```

4. Запустите бота заново. В Docker `127.0.0.1` указывает на контейнер бота: используйте имя сервиса в общей Docker-сети или доступный адрес хоста. Бот отправляет файлы multipart-загрузкой, общий каталог с Bot API не нужен. Не открывайте локальный Bot API в публичную сеть без ограничения доступа.

Даже локальный Bot API не отправит файл больше 2000 МБ. Место для временных данных ограничено примерно четырьмя лимитами файла на задачу, чтобы вместить отдельные потоки и результат объединения. Проверка происходит каждые 0,5 секунды и не заменяет дисковую квоту сервера. Для двух загрузок с лимитом 1990 МБ выделите хотя бы 16 ГБ свободного места.

## Настройки

| Переменная | Значение по умолчанию | Назначение |
| --- | --- | --- |
| `BOT_TOKEN` | обязательно | Токен от BotFather |
| `ALLOWED_USER_IDS` | пусто | Кто может скачивать |
| `MAX_UPLOAD_MB` | 49 | Предельный размер результата в десятичных МБ |
| `MAX_CONCURRENT_DOWNLOADS` | 2 | Число одновременных задач, по одной на пользователя |
| `DOWNLOAD_TIMEOUT` | 900 | Общее время получения метаданных и загрузки, секунды |
| `MAX_DURATION_SECONDS` | 7200 | Лимит длительности видео |
| `TELEGRAM_API_BASE` | пусто | Адрес собственного Bot API |
| `COOKIES_FILE` | пусто | Путь к cookies в Netscape-формате, если требуется вход |

Кнопки действуют 15 минут и до перезапуска бота. Новая ссылка пользователя заменяет предыдущий невыбранный запрос. При занятых слотах можно повторно нажать кнопку позже. Очередь загрузок не сохраняется при перезапуске.

YouTube и TikTok меняют защиту, а доступность зависит от региона и IP сервера. При ошибках сначала обновите загрузчик:

```bash
source .venv/bin/activate
python -m pip install --upgrade 'yt-dlp[default]'
```

В Docker для обновления: `docker compose build --no-cache`, затем `docker compose up -d`. Дополнение `[default]` устанавливает в том числе EJS; для YouTube нужен также Deno или Node.js. Подробности: [yt-dlp EJS](https://github.com/yt-dlp/yt-dlp/wiki/EJS).

При необходимости администратор может положить отдельную копию cookies в Netscape-формате и задать `COOKIES_FILE`. Бот не принимает cookies от пользователей в чате. Файл должен быть доступен процессу на чтение и запись: yt-dlp обновляет cookie jar. Не храните cookies в Git. Доступ к закрытым, платным и защищённым материалам не гарантируется; обход DRM не реализован.

## Проверка

```bash
source .venv/bin/activate
python -m unittest discover -s tests -v
```

Тесты проверяют ссылки, параметры команд, ограничения, остановку реального дочернего процесса по таймауту, владение кнопками, повторные нажатия, освобождение слотов и очистку файлов. Они не обращаются к Telegram / YouTube / TikTok. Для проверки живой загрузки нужны действующий токен, установленные FFmpeg и JS runtime и доступная ссылка.
